# Design

## Context

See proposal.md (Why). The plan rests on a survey of all ten public pages in Chromium with touch emulation at 390×844, 390×664 (the visible area of Safari on an iPhone with its toolbars), 360×780, 430×932, 320×568 and in landscape at 667×375, 844×390 and 932×430, plus one WebKit pass. Every fix below was first prototyped by injecting CSS and script into the published pages and measured there, and the same injection at 1440×900 and 1680×1050 changed no pixel. The measured figures quoted here come from that survey.

The constraints that shape the approach:

- **The living specs are the base.** `add-seo-and-sharing` is archived: `site-metadata` exists, and `playground-hub` "Playground routes" already carries the 404 page and the site files. Every MODIFIED requirement of this change is copied from `openspec/specs/` and edited.
- **One canvas over every page.** Each work paints all its views with one `position: fixed` WebGL canvas at `--engine-z`, above the DOM. `position: sticky` creates a stacking context. An opaque panel above `--engine-z` hides the view under it; an element below it disappears where a view is painted.
- **Each work has its own phone breakpoint**, tied to its layout: the museum `(max-width: 759px)`, Bloomscope `(max-width: 699px) and (min-height: 521px)` and its landscape `(max-width: 1023px) and (max-height: 520px) and (orientation: landscape)`, Game Center `(max-width: 767px)`, Wind-Up Empire `(max-width: 900px)`, `(max-width: 560px)` and `(max-width: 400px)`, and the 4D.OS narrow query `(max-width: 760px), (orientation: landscape) and (max-height: 500px)` (820 px for world C).
- **The loops.** The six museum loops were recorded at 1440×900 (world C at 1680×1050), dpr 1, `hasTouch: false`, `isMobile: false`, with Playwright 1.63.0 driving Chromium on the GPU (`--use-angle=metal`), as each `provenance.json` records. `src/engine/` and `src/4d-os/launcher/` are in every sheet's `sources` (`CORE` in `src/playground/museum/collection.ts`), and so are each world's page and code and Bloomscope's. `tools/capture-loops.ts` refuses to record uncommitted sources.
- **The head plugin** (`src/site/head.ts`) replaces a `<link rel="icon" href="data:,">` placeholder where it stands and adds the site's icon to any page that declares none. Its test fixture for world B is an inline copy, so editing `sites/4d-os/b/index.html` does not break it. `src/site/pages.test.ts` and the build fail when a page's meta description differs from its registry entry.
- **Tests run in Node.** `vitest.config.ts` sets no DOM environment. DOM behavior is checked in a browser (design D18); unit tests cover pure functions.
- **Share images.** Each image's band text comes from its card in `src/site/og/cards.ts`, not from the registry's title or description, so the edits of D12 and D13 do not require composing the images again.
- **Safe areas.** Only Game Center declares `viewport-fit=cover` (`sites/playground/landings/game-center/index.html`), so only there can `env(safe-area-inset-*)` be larger than 0: on an iPhone in landscape its content reaches under the sensor housing and the rounded corners. Every other page leaves the viewport meta as it is, and the browser keeps their content out of the notch and the home indicator.
- **No engine binding learns new nodes.** `bindDesktop` (`src/engine/shell/desktop.ts`) collects its `[data-now]` nodes once, when it is called, and Game Center's `floors.ts` binds the one `[data-lift]` and `[data-lift-now]` it finds at load. A node created later by a phone gate is invisible to both, so every such node is written or wired by the code that creates it (D7, D10).

## Goals / Non-Goals

**Goals:**
- On phones, every control is operable while its effect is on screen, every real control has a 44 px touch target, and no gesture competes with scrolling except from a grip or a control built to be dragged.
- One small vocabulary for the whole playground, applied in each work's own language.
- At 1440×900 and 1680×1050 with a mouse, every page paints the same pixels except the wording of D15, and the six loops keep every frame.
- Every phone rule can be checked in a browser from a fresh clone.

**Non-Goals:**
- Tablets in portrait (700–1023 px) as a design target. Coarse-pointer rules also reach them, and nothing more.
- Adding `viewport-fit=cover` to any page that lacks it. Without it `env(safe-area-inset-*)` is 0 and the browser keeps content out of the notch and the home indicator. Paddings keep their `env()` terms, so a later change can add it. Game Center already declares it, so its new phone blocks pad for the insets (D7).
- Compressing the packs, and any change to the files under `sites/4d-os/public/packs/`.
- Any change to the desktop design, including known desktop defects (D20).
- Production deploy.

## Decisions

### D1. One phone vocabulary: five patterns and four micro-rules, and no drawer

Every section of every page uses one of five patterns:

| Pattern | Use it when | How it behaves | Where |
|---|---|---|---|
| **Pinned stage** | A toy's visual and its control stack cannot share one phone screen, and the controls change the visual continuously. | The visual pins at the top (`position: sticky`) while its own controls scroll beneath it. The section's copy comes before the stage. The stage releases when the section's controls end. It is painted in the section's own field, with a hard edge and no fade. | Bloomscope Sow and lathe; Game Center 4F; Wind-Up Empire's proof bed (a small stage) |
| **Stage deck** | A pinned 100svh gesture hero whose first-screen controls have a global effect. | The controls live inside the pinned hero, docked to its bottom edge in rows of at most 44 px. The camera frames the free glass between the title block and the deck, read from live rects. The same nodes are moved in by `matchMedia`, never cloned. | 4D.OS D (as built) and E |
| **Window dock** | Many independent tool windows that would stack 1 to 2.5 screens below the viewer. | A row of disclosure buttons, one per window, with at most one window open. In the flow under the transport (A, C), or inside the pinned hero (B). | 4D.OS A, B and C |
| **Bottom bar** | One primary control or one route that must stay reachable while reading. | A bar on the work's own surface with its own 1 px rule and `padding-bottom: calc(8px + env(safe-area-inset-bottom))`. Its height is a CSS variable that feeds `body { padding-bottom }` and `scroll-padding-bottom`. Fixed for the whole page (the museum clock), or sticky only while its natural place is below the fold (the Wind-Up Empire band). | Museum clock; Wind-Up Empire band |
| **Side by side** | Any section on a phone in landscape. | The visual on the left, fitted to `100svh` minus the chrome; controls and copy on the right. A top bar without live state is never sticky in landscape. | Every page |

The micro-rules:

- **The drawing stays, the hit grows.** Where a control's drawn size is part of the world's language (the museum's marks, A's 3 px grid, D's stroke keys, the museum scrubber), the drawing keeps its size and a transparent, centered hit area of at least 44 × 44 CSS px grows around it with `::before` or `::after`. On each axis, a pseudo hit area is allowed only where `(44 − a)/2 + (44 − b)/2 ≤ gap`, with `a` and `b` the drawn sizes of the control and its neighbor on that axis and `gap` the space between their drawings; otherwise the real cell grows (D, E and the chip rows). So no two hit areas ever intersect, which the harness asserts (D18).
- **A grip, not a strip.** A gesture that competes with vertical scrolling is claimed only from a visible grip or a control built to be dragged: the museum's ground-line grip and the round face of Wind-Up Empire's key (`touch-action: none`), the outer ring of Bloomscope's dial (D6), and the Wind-Up Empire rocket, which claims only a pull-back: it keeps `touch-action: pan-y`, valid in every engine, and a non-passive `touchmove` listener calls `preventDefault` on the first move only when that move pulls away from the Whirl (D8).
- **The result goes to the toy.** Feedback appears where the hand already is: the key's tag stub, the Bloomscope chip flying into the pinned peephole, the Game Center ticket rack under the crane, E's NOW line in the deck.
- **The hold trio.** Every held button gets `touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none`.

Sizes and stacking shared by all works:

- **Targets:** 44 × 44 CSS px on a coarse pointer; world A uses 45 px, 15 of its 3 px units. Links inside sentences and the focus-only skip link are exempt. Letters of one word laid edge to edge as separate controls (Game Center's gas-sign tubes, D7) may be 40 px wide below 390 px, if each is at least 52 px tall and no two overlap: eight 44 px tubes do not fit the roughly 328 px a 360 px screen leaves, and 40 × 52 is still well above WCAG 2.5.8's 24 px minimum.
- **Contrast:** every element created or restyled under a phone gate reaches 4.5:1 for text and 3:1 for glyphs, grips and focus indicators against what is painted behind it, measured by the harness (D18). Where a work's desktop color fails that bar on an element the phone skin restyles anyway (B's window legends and asides), the phone skin fixes it (D9).
- **A pinned stage** takes at most 56% of `svh` (Bloomscope 268 px at 390×844; the Game Center glass `min(100%, 56svh − 105px)`).
- **Units:** `svh` for everything pinned or sized to the screen, never `dvh`, which resizes views on every toolbar change and forces an engine relayout mid-scroll.
- **Stacking:** a pinned stage whose view the body-level canvas paints sits below `--engine-z` and above the controls that scroll under it (Bloomscope `z-index: 2`, Game Center `calc(var(--engine-z) - 1)`). A stage deck or window dock inside a hero's own sticky layer sits at `calc(var(--engine-z) + 1)` in its own stacking context, with opaque cards. `mix-blend-mode` is never used across a stage. An `--over-engine` child that overlaps a view inside a stage is moved off the view (Bloomscope's "GOLDEN").
- **Focus not obscured:** controls under a pinned stage get `scroll-margin-top` equal to the stage's height plus 12 to 16 px; pages with a bottom bar get `scroll-padding-bottom: calc(var(--bar-h) + M)` on `html`.
- **Text:** body and sentences at least 12 px; control labels and "synthetic" tags at least 11 px (Game Center keeps its own 12 px for push buttons). Retro readouts in a screen typeface, scale annotations and units inside large numerals are exempt.
- **Motion:** no pattern animates by itself; sticky is not motion. The window dock opens and closes instantly in every mode. The only new movement is the museum's post-fold scroll (D4).

**Alternative rejected: a drawer or bottom sheet for the controls.** A sheet must sit above `--engine-z` to be seen, and there it covers the view it controls. The lathe's controls are about 660 px tall and do not fit a peek row, so a sheet would need an expanded state or tabs, which hide working controls. It would also add open and close state, focus management and a drag that competes with vertical scrolling. The pinned stage shows the effect with no extra tap. Also rejected: segmented tabs over one control stack (they hide working controls, and the pinned stage makes a long stack harmless), horizontal control rails (a slider inside a sideways scroller fights the rail's own swipe), controls overlaid on the visual (they sit under the canvas or cover the view; D and E are the exception, because their deck writes on glass and void fields), and scrolling the page to show a result (it takes the scroll from the visitor; the one exception is D4's post-fold scroll, guarded and instant under reduced motion).

### D2. Gates: each work's own queries, the same strings in CSS and script

| Purpose | Query |
|---|---|
| Layout on phones | Each work's existing phone breakpoint, unchanged (see Context). No work gains a width breakpoint above 900 px. |
| Landscape phone | `(orientation: landscape) and (max-height: 500px)`. Game Center adds `and (pointer: coarse)`, because its existing `(min-width: 768px) and (max-height: 560px)` rule serves short desktop windows. Bloomscope keeps its existing landscape query (520 px). Wind-Up Empire's earlier draft `(max-width: 900px) and (max-height: 500px)` is replaced by this query, because it missed 932×430 and 926×428. |
| Targets, grips, the hold trio, touch-only hints | `(pointer: coarse)`; `(hover: none) and (pointer: coarse)` to hide keyboard hints |
| Short portrait phones | `(max-height: 760px)` joined to the work's phone width (only Wind-Up Empire) |
| Script gates | `matchMedia` with the same string as the CSS gate, evaluated again on `change`; what a gate created is removed and every attribute it set is restored when it stops matching |

None of these can match at 1440×900 or 1680×1050 with a mouse: every width-only gate stops at 900 px; a wider width gate (Bloomscope's 1023 px landscape) is always joined to a height of at most 520 px or to landscape with a height of at most 500 px; every height gate stops at 520 or 760 px and is joined to a phone width or to landscape; and `(pointer: coarse)` is false. The harness asserts it (D18).

One script gate is read once on purpose: Wind-Up Empire's rendering budget (D8), because the renderer's pixel density and scene detail are fixed when it is built. Its query matches a phone in both orientations, so rotating the phone does not change the answer.

Media queries use comma lists, never the Media Queries Level 4 `or` keyword: an older mobile Safari parses a query with `or` as `not all`, which would silently turn a phone rule off.

**Alternative rejected: one new site-wide phone breakpoint.** Each work's layout already turns at its own width; moving those widths would change layouts between 760 and 1023 px that no phone uses and that the desktop checks do not cover. Coarse-pointer rules also reach tablets and touch laptops, which get larger hit areas and grips. That is accepted: nothing is recorded there.

### D3. Phone-only elements are created by script under the gate

Nodes that exist only for phones (the museum's grips, Bloomscope's peephole counts and its `hive-put-row` class, Game Center's elevator call buttons, Wind-Up Empire's stub, coil, key grip, proof bed and deck link, the window dock, E's deck and its NOW mirrors, the launcher's stills, its "still" tags, its "Run the scene live" button and its live node) are created by each page's script while the gate matches and removed when it stops matching. Moves use the same nodes (Bloomscope's peepholes and hints, E's fieldsets, D's monitor as today). The desktop document therefore keeps its element counts. Whatever a gate creates is written and wired by the code that creates it, every time it creates it, because the engine's bindings never see a node added after they ran (Context).

The static markup changes are limited to: the `<title>`, meta descriptions, `data:,` lines and copy of D12 to D14; `theme-color` metas on the launcher and E; A's Label section moving after its drawers and C's strip moving before its cards (focus order follows the phone's visual order, `desktop-shell` "Narrow viewport"); and a span around the word "frame" in D's timeline head, which renders the same text on every screen.

**Alternative rejected: static markup hidden with `display: none` on desktop.** It changes the desktop document (the release fingerprint counts elements), reaches pages without JavaScript as dead controls, and needs a CSS rule on every width to hide it.

### D4. Museum: a shedding bar, a refined clock bar, grips and a landscape range

- **Top bar (portrait, `(max-width: 759px)`):** `position: sticky` with `top: calc(-1 * var(--bar-title-row))` (30 px), so the title row scrolls away and only the navigation row stays, 45 px. `.bar__title` gets `white-space: nowrap; line-height: 20px` so the offset stays exact. `scroll-padding-top` becomes 61 px. Pure CSS, no scroll listener.
- **Clock bar:** stays the fixed bottom bar and is the reference bottom bar of D1. The states lose most of their tracking, so the scrubber measures 81 / 121 / 151 / 191 px at 320 / 360 / 390 / 430. `--clock-h: 79px` feeds `body { padding-bottom }` and `scroll-padding-bottom`, replacing two hard-coded `96px`. Chrome while reading goes from 147 px (17.4% of 844) to 124 px (14.7%).
- **Targets (`(pointer: coarse)`):** hit areas of 44 px on `.bar__link`, `.bar__button`, `.clock__state`, `.clock__scrub` (a `::before`, because `.clock__state::before` draws the state dot) and `.tool`; full-width rows ("Sheet data", "Enter <title>", "Keyboard shortcuts", the "House pixels" labels) become 44 px tall.
- **Ground line:** under `(pointer: coarse)`, `.ep-hinge { pointer-events: none }` and the script skips its `touchstart` `preventDefault`, so a swipe over an épure scrolls. The script creates one `<span class="ep-grip" aria-hidden="true">` per épure: a 14 px square ink mark split by the ground line at its right end, flush with the épure's right edge, with `touch-action: none` and a 44 px hit area whose right edge is the mark's right edge, so it grows 30 px to the left and 15 px up and down and never passes the viewport's right edge. As built, the span itself is the 44 × 44 hit box (`right: 0; top: calc(62.5cqi - 22px)`, with `container-type: inline-size` on `.sheet__epure` under the same gate) and its `::before` draws the 14 px mark at its right edge, 15 px from its top: the same geometry with the hit area as the element, which the target probe measures directly. The grip is hidden while its sheet is folded (`.sheet__epure.is-folding .ep-grip { visibility: hidden }`), because `container-type` makes `.sheet__epure` a stacking context below the engine canvas and a grip drawn there would float over the folded 3D view. Its `pointerdown` calls the existing `dragHinge`; a tap (under 8 px of movement) calls `toggleFold`. The grip is square so it is never read as the NOW. "Fold" and F stay the accessible path.
- **Fold in view:** when a fold settles at `(max-width: 759px)` and the fold view's bottom lies under the clock bar, the page calls `scrollIntoView({ block: 'nearest' })`, smooth or instant under reduced motion, unless the visitor touched or scrolled since the fold began (the same guard as the deep link).
- **Landscape (`(orientation: landscape) and (max-height: 500px)`, after the portrait block):** a static one-row bar, the clock docked in one 47 px row (states, a long scrubber, the loops line in two lines at the right), each single-VISTA sheet with the VISTA fitted to the height beside its épure (221 px, k = 3, at 667, 844 and 932 wide), and sheet 001's three VISTAS side by side.
- **Index (`(max-width: 759px) and (orientation: portrait)`):** number and form above the poster in a 5M column, the text in the remaining width; the list goes from 1023 to 954 px at 390, and "14.0 s · 420 frames at 30 fps" fits one line. DOM order is unchanged.

**Alternatives rejected:** a grip hit area centered on the mark at the épure's edge (`right: -22px`; it reaches about 6 px past the viewport at 390, which the right-edge probe flags, and puts more of a touch-capturing square into the right thumb's scroll lane); a hide-on-scroll-down header (a motion the museum's grammar forbids, and a scroll listener); a non-sticky bar with Index moved into the clock (the clock row is full, and the loops line must stay beside the clock); a pinned VISTA (it leaves about 300 px to read the épure and text, and sheet 001's three VISTAS are 640 px tall); direction detection on the ground line (impossible after `preventDefault` on `touchstart`, and without it Chromium scrolls, because it ignores `touch-action` on SVG shapes); dropping the ground-line drag on touch (it loses a specified gesture).

### D5. Museum scrubber: no drag autoscroll and a truthful position, on every device

Two defects of the page clock's scrubber are not phone-only:

- A pointer drag on `.clock__scrub` starts the browser's drag autoscroll and runs the page to the top (a 12 px drag moved the page by 1656 to 2070 px), because its `pointerdown` handler calls `setPointerCapture` but not `preventDefault`. The handler calls `event.preventDefault()` and then `scrub.focus({ preventScroll: true })`, because preventing the default also prevents a mouse press from focusing the scrubber, and the arrow keys must keep working after a drag. The scrubber also gets `user-select: none; -webkit-user-select: none` next to its existing `touch-action: none`.
- `aria-valuenow` is written only while the clock is stopped, so while it runs a screen reader reads a stale frame (12 while the knob is near 40). Screen readers announce every value change of a focused `role="slider"`, so the fix must not turn the scrubber into a metronome. The rule, in one pure helper (`clockAria(state)` in a new `src/playground/museum/clockAria.ts`, with its tests):
  - on the scrubber's `focus` event, and at once on every state change (FORWARD, REWIND, HOLD, a drag, an arrow key), `aria-valuenow` and `aria-valuetext` (`frame 40 of 45, playing forward`, or `rewinding`, or `held`) are written with the drawn position;
  - while the clock runs and the scrubber does not have focus, they are written at most once per second, on the first painted frame after a second has passed since the last write; nothing announces them, because nothing has focus on them;
  - while the clock runs and the scrubber has focus, nothing is written until focus leaves or the state changes; on `blur` the throttled writes resume.

  In HOLD the value equals the drawn position, as today.

These are behavior fixes, ungated. At rest they change no pixel, and no loop records the museum.

**Alternatives rejected:** writing the value at most once per second in every case, focus included (a screen-reader user who tabs to the scrubber hears one announcement a second for as long as the clock runs, which is exactly why the value was withheld); gating the fix behind `(pointer: coarse)` (the autoscroll also happens with a mouse); writing the value on every frame (15 announcements a second); keeping the value frozen while the clock runs (it reports a position that is not shown to anyone who reads it without focusing the scrubber, such as a screen reader's virtual cursor).

### D6. Bloomscope: a pinned stage for Sow and the lathe, the peephole beside the toy

- **Gates:** portrait `(max-width: 699px) and (min-height: 521px)`, the query `main.ts` already uses for its inset move; landscape `(max-width: 1023px) and (max-height: 520px) and (orientation: landscape)`, already in `style.css`.
- **Stage (portrait):** `.toy` becomes `position: sticky; top: 0; z-index: 2`, a two-column grid of `var(--stage-s)` and a 96 px peephole, on the section's field (`--lilac` or `--glaucous`) with `box-shadow: 0 2px 0 var(--ink)` and full-bleed margins. `--stage-s: min(calc(100vw - 32px - 96px - 10px), calc(46svh - 16px))`: 252 px at 390, 222 at 360, 292 at 430. `top: 0` is right because the top bar is `position: absolute`. The stage is contained by `.bench-body`, so it releases after Pixels (lathe) or the herbarium (Sow).
- **Copy above the stage without moving the DOM:** `.bench-copy { display: contents }` and `order` (sub −2, toy −1, hint −1, controls 0); DOM and tab order stay as they are.
- **Two moves in a new `src/playground/bloomscope/stage.ts`** (`bindBenchStage(onLayout)`, about 50 lines): under the two gates joined in one `matchMedia`, each bench's `.peephole` goes into `.toy` (Sow and lathe) or after the Hive's "Put in the Scope", and each `.toy-hint` goes right after `.toy`; `stage.ts` also sets the class `hive-put-row` on the row that holds the Hive's Put while the gate matches and removes it when the gate stops matching. Everything returns when the query stops matching, and `onLayout` calls `invalidateLayout()` on the engine (or dispatches `resize` on the 2D fallback). `main.ts` binds it next to the existing inset move, on both the WebGL2 and the 2D paths. `sites/playground/bloomscope/index.html` does not change.
- **Landscape:** the stage is a sticky left column (`grid-row: 1 / span 3`), copy and controls on the right; the Hive frame on the left at `min(100%, (100svh − 56px) × 1.78)` wide.
- **The chip goes to the peephole:** `putInScope` in `bench/common.ts` takes an optional peephole element; when a stage gate matches and that peephole intersects the viewport, the chip flies into it and `chamber:incoming` is not dispatched, so the gem stays tucked. `main.ts` passes each section's `.peephole-view`. Because the tucked gem is what shows the count, `stage.ts` also creates, under the gate, an `aria-hidden` count on each moved peephole's frame (`n/7`, set in the gem's own typography, on the stage's field outside the view's circle), updated from the same chamber change that updates the gem; and the section's existing live region (`.sow-live`, `.lathe-live`, `.hive-live`) announces "In the chamber: n of 7" after each Put, "Chamber full" at 7.
- **GOLDEN** moves onto the dial's band at 12 o'clock (`top: -4px`, 16 px mono) inside the stage, outside the view's rectangle, because a stage below `--engine-z` hides over-engine children where the canvas paints.
- **Dial grip:** while `(pointer: coarse)` matches, `SowController` sets the outer grip ring's `stroke-width` to `44 / scale` (with `scale = dialWidth / 640`) and its `r` to `min(bandIn + 22 / scale, boxR − 22 / scale)`, where `boxR` is half the dial's own SVG box: the ring grows inward where it would otherwise pass the dial's box, so its hit band never reaches outside the dial and cannot steal a tap from the controls that scroll out from under the pinned stage. It is recomputed on resize and on the query's change; `.toy .peephole` gets `position: relative; z-index: 7` so the ring never steals the peephole's taps. Hit strokes are transparent: no pixel changes.
- **A touch on the ring turns the dial.** Chromium ignores `touch-action` on SVG shapes (D4), so under `(pointer: coarse)` the ring gets a non-passive `touchstart` listener that calls `preventDefault`: a drag that starts on the ring, in any direction, turns the dial and never scrolls. The ring is a control built to be dragged, like a jog wheel (`phone-ergonomics` "Scrolling is never trapped"); a vertical swipe that starts on the plate inside the ring, or anywhere else on the stage, scrolls.
- **Focus:** `scroll-margin-top: calc(var(--stage-s) + 32px)` on the bench-body children and the controls in the bench copy, under the portrait gate.
- **Also:** the hold trio on `.sow-hold`; footer links and the wordmark at `min-height: 44px` under `(pointer: coarse)`. The Hive keeps no stage: its frame and controls already share a screen. If the harness finds it failing at 390×664, it gets the same stage, with no new vocabulary.

**Alternative rejected: a bottom sheet holding the controls** (D1). Also rejected: `overflow: clip` on `.toy` to contain the ring (it would also clip GOLDEN, which sits on the band's top edge at `top: -4px`); letting a vertical swipe on the ring scroll (with `preventDefault` decided after the first move, a ring drag that starts downward would scroll instead of turning, and Chromium gives no `touch-action` on SVG to express "rotate only"); shrinking the toy further to fit controls beside it in portrait (a 222 px toy is already the floor at 360; the next lever, if the seed head reads poorly on a device, is an 88 px peephole).

### D7. Game Center: cabinet hardware that fits, and a pinned glass on 4F

- **1F deck at real heights (`(max-width: 767px)`):** the deck stops shrinking with `--du: max(var(--u), 1px)` and anchors to the cabinet's bottom; the bezel takes what is left (`bh = 747·u − 254·du`), and the CRT, the time strip and the HUD sizes derive from `bh`. At u ≥ 1 (390×844 and taller) nothing changes. Below 360 px wide, `--du` floors at 0.889px and START rises 6 px. Measured: no intersection and every target at least 44 px at 390×664, 360×640 and 360×560; the CRT stays 3:4.
- **The hold trio** on `.stick__dir`, `.arcade` and `.start` (the crane buttons and LAUNCH already have it); a 44 px hit box on `.timestrip__range` (`block-size: 44px; margin-block: -13px`), both under `(pointer: coarse)`.
- **1F in phone landscape (`(orientation: landscape) and (max-height: 500px) and (pointer: coarse)`):** a handheld cabinet: a slim 40 px marquee, the 4:3 CRT centered at full height, the joystick in a cobalt left wing and A, B, C and START in a right wing, each wing at least 150 px, all within `100svh`; below 768 px wide the utility row (sound, elevator, 2F link) moves to the top of the wings. Nothing is sticky.

### D9. Worlds A, B and C: one window dock in three skins

A new headless helper in `src/engine/window/dock.ts`, next to `windows.ts` and following its convention (classes and attributes, no styles):

```ts
export interface DockOptions {
  query: string;                      // the world's narrow query
  windows: string[];                  // data-window names, in button order
  mount: (bar: HTMLElement) => void;  // where the world puts the button row
  initial: string | null;             // window open on entering the query
  label?: string;                     // group name, default "Windows"
  onChange?: (open: HTMLElement | null) => void; // after each open, close or switch (B reframes)
}
export function bindDock(options: DockOptions): () => void;
```

On entering the query it creates `<div class="dock" role="group" aria-label="Windows">` with one `<button type="button" class="dock__button" aria-expanded aria-controls>` per window, named after the window's title; calls `mount`; sets `html[data-dock]`, `data-docked` on each window and `hidden` on the closed ones; and binds click and Escape. Leaving the query reverses all of it. It never reparents windows, never scrolls (no `scrollIntoView`; focus returns with `focus({ preventScroll: true })`), and never touches `translate` or `z-index`, which `bindWindows` keeps owning. Each world's CSS adds `[data-docked][hidden] { display: none !important; }`, because author rules that set `display` on a window beat the user-agent `[hidden]` rule. Buttons and windows use `touch-action: pan-y`, so a swipe on the dock scrolls (in B, it drives the hero). Pure helpers (`nextOpen(current, pressed)`, the label extraction) are unit-tested in `dock.test.ts`; the DOM behavior is checked in the browser.

### D16. Proving the desktop did not change, in three layers

1. **Deep desktop screenshots.** `tools/check-phone.ts desk` renders every page at 1440×900 and 1680×1050 (and the museum also at 1100×800 and 760×1000) with `hasTouch: false`, `reducedMotion: 'reduce'`, a fixed clock, fonts loaded and the 4D.OS pages' time held at frame 0, and screenshots the top, every section and the end, plus a dump of each element's box and computed style. `desk-compare` passes when the images are byte-identical outside the boxes of D15's copy lines and the dumps are equal apart from those lines' text and D15's element moves. It runs at two levels, always comparing like with like:
   - **while owners work**, on the development servers: a baseline `desk-before-dev` taken on development servers of the commit before this change, compared with the owner's working tree on development servers. It catches a leaking rule early; it is not the proof;
   - **the proof**, on production builds: `desk-before` on a build of the commit before this change, compared by the integrator with a build of the result.
2. **The release fingerprint.** The release fingerprint tool (kept outside the repository, as in `add-seo-and-sharing` D8) runs on both builds for the 10 routes, desktop, phone and without JavaScript. A small comparison script, also outside the repository, applies D15 entry by entry: text equal after the listed substitutions, the two block moves as multiset-equal text, element-count deltas exactly `{SPAN: +1}` on D and the head counts of D15, request deltas exactly E's source pages, pixels equal in the first viewport except the launcher's bar note. Phone entries are expected to differ; they are reviewed against the phone checks, not counted as failures.
3. **The loops** (D17).

In every desktop context the harness also evaluates every new media-query string and asserts `matches === false`.

**Where proofs run.** Seven owners edit one working tree at the same time, so none of them builds it: `npm run build` starts with `tsc --noEmit` over `src` and `tools`, which fails on any other owner's half-written file, and two `rm -rf dist` runs would clobber each other and the servers that serve `dist/`. So owners work and self-check on the development servers (`vite` serves without type-checking, and the metadata plugin runs only in builds), and never write `dist/`. Only the integrator builds and serves the production build, runs every proof on it, and sends each failure back to the file's owner. Before handing over, each owner's `npm run typecheck` reports no error in its own files. Checks that depend on production bundling (load times under throttling, transfer budgets, the metadata heads) are proven only on the build.

**Alternatives rejected:** the fingerprint alone (it screenshots only the first viewport of each page, so it cannot see the footers or Room 7, and its comparison truncates diffs and knows no allowlist); one git worktree and one `dist` per owner (seven installs and seven builds, and each owner's proof would still miss the other owners' changes, which the integrator must check anyway); one shared build slot that owners take in turn (it serializes the owners on the slowest step and still needs a clean whole-tree typecheck mid-flight).

## Risks / Trade-offs

- [A phone rule leaks to the desktop] → every rule sits inside a named gate; the harness asserts each query is false on desktop, D16 compares deep screenshots, and D17 re-records the loops and compares every hash before anything is kept.
- [Sticky over the engine canvas] → stages stay below `--engine-z` and decks and docks above it inside their own stacking context (D1); the harness takes screenshots at three stuck scroll offsets of each stage to catch a view drawn at a stale rectangle.
- [Real iOS cannot be emulated: the collapsing toolbar under sticky and fixed bars, long-press callouts, D's floated legend, the Wind-Up Empire lid lift using `innerHeight`, the safe-area insets of Game Center's landscape handheld] → `svh` everywhere, the WebKit pass and injected fake insets; one pass on a real iPhone is listed as pending in `verification.md`.
- [Smaller visuals on small phones: Bloomscope's toy 222 px at 360, C's gate from 58 to 50 svh, E's scene about 268 px at 360×780, D's free glass about 250 px] → co-visibility is worth the size; the next levers are recorded (an 88 px peephole, C back at 58 svh with a 190 px scroll, D's pocket plotter at 112 px).
- [`(pointer: coarse)` on tablets and touch laptops, and the landscape query on desktop windows under 500 px tall] → visible there and accepted; no recorded viewport matches.
- [A touch on the Wind-Up Empire rocket that starts toward the Whirl must keep native scrolling] → one mechanism in both engines (`pan-y` and a first-move `preventDefault` only for a pull-back); the WebKit check confirms that the page keeps scrolling after the finger lifts.
- [A's Label move changes `bindWindows`' z-index order on desktop] → the Label overlaps nothing at 1440 or 1680; if D16 shows a difference, the move is dropped.
- [The Bloomscope Hive and the Wind-Up Empire compact lid were not measured at 390×664] → the harness decides: the Hive gets the same stage, and the lid's clamp floor rises, if either fails.
- [Launcher stills first changes the phone's first impression from live to still] → 53 MB for three thumbnails is not acceptable on a phone; the live scene is one tap away on the first screen, each still is tagged as a still, and the weight is stated on the button.
- [Owners working in one tree at once] → owners self-check on development servers and hand over with a clean typecheck of their own files; only the integrator builds and proves (D16).

## Migration Plan

1. Implement on the feature branch in the order of D19 (the harness first, then the six work owners in parallel), then the integrator commits the implementation (Conventional Commits, one or more `feat`/`fix`/`docs` commits; the five description edits in the page HTML and `src/site/pages.ts` in the same commit, because the build compares them).
2. Record the loops (D17) in their own commit.
3. Archive the change and update `docs/openspec-workflow.md`.
4. Merge the branch **without squashing**: each loop's provenance names the commit it was recorded at, and `public-repository` "Clean public history" requires that commit to exist in the published history. `verification.md` and the hand-over summary to whoever merges both state it.
5. Deploy later through `playground-hub` "Preview before production". Rollback is a revert of the implementation commit and of the loop commit together.
